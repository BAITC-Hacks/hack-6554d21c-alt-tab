# Saqta Insurance — симулятор разговора

## Назначение и границы

Один экран для разговора клиента и наблюдения за маршрутизатором. React + TypeScript + Vite, русские подписи и казахский текст. Изменения только в frontend/; сервер, исходные данные и инфраструктура принадлежат другим участникам.

## Экран

Вверху — Saqta, явный Live / Mock и новый диалог. Слева — лента, управление голосом и текстовый резерв; справа — трасса выбранного хода. На телефоне трасса под разговором. Светлая поверхность, синий акцент, бирюзовая готовность, янтарное подтверждение. Системный шрифт Segoe UI / Arial без внешних запросов.

Трасса показывает сценарии/confidence, альтернативы, причину, языки, continuation, решение, активный сценарий и очередь, слоты, действия preview/execute, pending_confirmation, handoff, ошибки и метрики. Handoff отмечен как симуляция. Подтверждение — обычная реплика, решение принимает сервер.

## Архитектура v2

- src/api/types.ts: Zod-схемы health, session, TurnResult и LiveKit credentials.
- src/api/client.ts: REST health, создание сессии, текстовый ход, история, выдача комнаты. Повтор сохраняет request_id, timeout 90 секунд. Отбрасывание неожиданного audio_url сохраняет результат действия.
- src/api/mock.ts: отдельный явный адаптер примеров без анализа текста и речи.
- src/useConversation.ts: состояние сессии, блокировка повторной отправки, дедупликация истории по turn_id, сортировка, защита от поздних HTTP-ответов старой сессии.
- src/voice/livekit.ts: разрешение микрофона, динамический SDK, комната, публикация и удалённое аудио, проверка пакетов, освобождение ресурсов.
- src/components/VoiceControls.tsx: состояния подключения, autoplay, ошибки и периодическое восстановление истории. Компонент пересоздаётся при смене сессии.

Контракт REST и команды запуска приведены в README.md. Клиент не обращается к провайдерам напрямую и не хранит их ключи. SERVER_API_TARGET задаёт только dev proxy. Автоматического перехода в Mock нет.

## Голос и восстановление

Разрешение микрофона предшествует POST /livekit. Комната публикует микрофон и прикрепляет аудио удалённого агента. DataReceived разрешает только saqta.trace/error/ready от удалённого isAgent; trace/ready должны соответствовать сессии. Валидная трасса подтверждает активность даже при потере ready. Ready означает запуск агента, не успешный цикл STT/TTS.

Autoplay block показывает кнопку room.startAudio(). При завершении освобождаются треки и комната. Поздний getUserMedia после отмены также освобождается. Текст, переключение режима и новый диалог заблокированы во время голосового соединения.

GET /turns восстанавливает историю по событиям комнаты, после ручного завершения, по кнопке и каждые 4 секунды активного соединения. Смена говорящего не пересоздаёт интервал. voice_configured позволяет попытку соединения при voice_ready=false с честной подписью.

## Метрики и проверка

Текстовый резерв не озвучивается, файловое аудио не используется. Серверные метрики показываются как получены, null — «не измерено». Голосовая E2E неизвестна без отдельного измерения конца речи и начала каждого ответа; подключение аудиотрека не заменяет такой замер.

Unit/component-тесты проверяют адаптер, состояние, FakeRoom и управление голосом. E2E проверяет RU/KK/mixed, preview, handoff, новую сессию, ошибки/повтор, отказ микрофона, освобождение искусственного микрофона и мобильную ширину. Реальный backend и WebRTC/STT/LLM/TTS требуют отдельной приёмки по README; аппаратные mute/unmute остаются ограничением.
