# Saqta Insurance — симулятор разговора

## Назначение и границы

Один экран для голосового разговора клиента и наблюдения за решением маршрутизатора. React + TypeScript + Vite, русские подписи, полноценный казахский текст. Изменения только в `frontend/`; сервер, исходные данные и инфраструктура принадлежат другим участникам. Никаких ссылок на материалы, откуда взяты данные, в пользовательском интерфейсе.

## Согласованный экран

Вверху — название Saqta, состояние соединения, явный выбор Live / Mock и новый диалог. Слева — лента реплик, запись и текстовый резерв; справа — трасса выбранной реплики. На телефоне трасса располагается под разговором. Спокойная светлая поверхность, глубокий синий акцент для записи и навигации, бирюзовый для готовности, янтарный для ожидающего подтверждения. Палитра: #F4F7FC, #FFFFFF, #173A70, #1D2638, #18756C, #9C5C16. Шрифт Segoe UI / Arial: системные гарнитуры с кириллицей и казахскими буквами, без внешних запросов.

Трасса отображает сценарии и confidence, альтернативы, причину, язык ввода и ответа, continuation, текущий сценарий и очередь, слоты и недостающие значения, действия preview/execute с результатами или ошибками. Отдельные панели показывают pending_confirmation и handoff с пометкой «симуляция». Подтверждение передаётся обычным текстовым ходом; браузер не решает, что клиент согласился.

## Контракт и состояние

API: GET /api/health; POST /api/sessions; POST /api/sessions/:id/turns с request_id/text; POST /api/sessions/:id/audio с multipart request_id/audio. Результат содержит session_id, request_id, turn_id, turn, mode, transcript, language, response_language, scenarios, alternatives, reason, is_continuation, decision, active_scenario, queued_scenarios, slots, missing_slots, actions, pending_confirmation, handoff, reply, audio_url, latency_ms, server_processing_ms, warnings.

Сервер владеет историей и бизнес-решениями. UI блокирует одновременные отправки, создаёт UUID для каждого нового запроса, повторяет неопределённый результат с тем же request_id. При ошибке нет автоматического mock-fallback. Режим ответа сервера всегда виден, даже если подключение выбрано Live. URL аудио допускается только same-origin. Ключей речи в браузере нет. Dev proxy настраивается SERVER_API_TARGET, не VITE_*.

Mock — отдельный демонстрационный адаптер с выбором примера: RU, KK, mixed, несколько намерений, preview/confirmation, handoff. Он не притворяется маршрутизатором и не читает размеченные ответы dev-набора в рантайме. Фактическое решение в Live приходит исключительно с backend.

## Голос и метрики

MediaRecorder выбирает поддерживаемый MIME, сохраняет правильное расширение файла, ограничивает запись 60 секундами и 10 MiB. Ошибки доступа, устройства, формата, записи и сети имеют понятные сообщения. Tracks освобождаются при остановке, отмене и размонтировании. Асинхронное разрешение микрофона после отмены немедленно закрывает полученные tracks.

Пока запрос выполняется, отображается только «Обработка голоса» или «Обработка текста». «Говорю» включается по событию playing. Autoplay failure даёт кнопку запуска звука, ошибка файла — отдельное сообщение. HTTP timeout 90 секунд; запросы отменяются при уходе со страницы.

null = «не измерено». Серверные этапы и server_processing_ms показываются раздельно. Локальный elapsed берётся от text submit или остановки записи до первого playing. Подпись честно указывает точку старта; ручной запуск после блокировки помечает включённое время ожидания пользователя. Это не VAD end-to-end.

## Приёмка

Production build без секретов. Автотесты API/таймаутов/ошибок, ограничений записи и измерений; браузерные проверки ленты, новой сессии, KK и mixed, смены темы, preview, handoff, отказа микрофона и autoplay. Live-голос считается проверенным только после реального STT/router/TTS round trip. При отсутствии сервера отчёт прямо отмечает блокер и request_id/turn_id, если они получены.
