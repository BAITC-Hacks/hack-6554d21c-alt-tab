# Saqta — голосовой симулятор

React + TypeScript + Vite. Диалог и микрофон слева, трасса выбранного хода справа. Русские подписи, казахский текст, RU/KK/mixed, очередь сценариев, preview/execute, подтверждение и передача оператору с пометкой «симуляция».

## Запуск

Нужны Node.js 24 и npm. Команды выполняются в frontend:

```sh
npm ci
npm run dev
```

Открыть http://127.0.0.1:5174. По умолчанию выбран Live, backend ожидается на http://127.0.0.1:8000. Для просмотра без backend переключитесь на Mock вручную.

Адрес backend можно задать в локальном .env:

```dotenv
SERVER_API_TARGET=http://127.0.0.1:8000
```

Это адрес dev proxy. Ключи LLM/STT/TTS и signing secret остаются на сервере; секреты нельзя помещать в VITE_*. Для голоса нужны настроенные backend, LiveKit и voice worker.

## API v2

| Метод | Запрос | Ответ |
| --- | --- | --- |
| `GET /api/health` | — | status, mode, voice_ready, voice_configured, missing_config, models |
| `POST /api/sessions` | `{}` | session_id, as_of_date |
| `POST /api/sessions/{id}/turns` | `{request_id,text}` | TurnResult |
| `GET /api/sessions/{id}/turns` | — | `{turns:[TurnResult,...]}` |
| `POST /api/sessions/{id}/livekit` | `{}` | room, token, ws_url, session_id, trace_topic: saqta.trace |

Ответы проверяются Zod. Сервер владеет историей и бизнес-решениями. Повтор текстового запроса сохраняет request_id; автоматического повтора мутаций и перехода в Mock нет. Текст ограничен 4000 символами, HTTP timeout — 90 секунд. Подтверждение действия отправляется обычной репликой; UI не вычисляет confirmed:true.

Mock использует выбранный пример, не анализирует произвольный текст и не запускает речь. Его confidence условный, задержки не измерены. Режим каждого результата явно показан, в том числе когда backend отвечает в Mock.

## Голос через LiveKit

Браузер получает разрешение микрофона **до** POST /livekit, подключается через livekit-client и публикует аудиотрек. Микрофон требует HTTPS либо localhost; для страницы HTTPS требуется WSS. SDK загружается динамически при подключении.

- Ожидание разрешения — до 15 секунд, подключения — до 30 секунд. После подключения агент должен подтвердить активность за 30 секунд через ready или валидную трассу.
- voice_configured=true разрешает попытку подключения при voice_ready=false; интерфейс сообщает, что живой голос ещё не проверен.
- Аудио и data packets принимаются от удалённого участника с isAgent=true. Известные topics: saqta.trace, saqta.ready, saqta.error. Для trace/ready проверяется session_id; error по контракту содержит stage, message и необязательный request_id.
- При блокировке autoplay кнопка «Включить звук» вызывает room.startAudio().
- История восстанавливается при подключении, ready, переподключении, завершении, ошибках пакетов и каждые 4 секунды активного соединения. В Live также доступна кнопка «Обновить историю». Ходы объединяются по turn_id и сортируются по номеру.
- При остановке, отмене и уходе со страницы освобождаются треки и комната. Позднее разрешение микрофона после отмены немедленно закрывает полученные треки.

Текстовый резерв не озвучивается. Файловое аудио не используется: неожиданный audio_url отбрасывается с предупреждением, сохраняя бизнес-результат. Во время голосового разговора текстовый ввод заблокирован.

null в метриках означает «не измерено». Серверные этапы показаны отдельно. E2E от конца речи до ответа не измеряется: подключение непрерывного аудиотрека не определяет начало каждого ответа.

## Сборка и проверки

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Для установленного Chrome в PowerShell:

```powershell
$env:PLAYWRIGHT_CHANNEL = "chrome"
npm run test:e2e
```

Playwright запускает production preview на 5175; перед E2E нужна свежая сборка. Тесты подставляют HTTP-ответы и используют искусственный микрофон. События комнаты и autoplay проверяются unit-тестами с FakeRoom. Эти проверки не подтверждают реальные WebRTC/STT/LLM/TTS.

npm run preview позволяет отдельно просмотреть сборку, но не проксирует API. В production раздавайте dist/ с origin, на котором доступны /api/*. Отдельный динамический LiveKit chunk превышает 500 kB; Vite сообщает предупреждение о размере.

## Ручная приёмка с реальным backend

1. Проверить health, создание сессии и текстовый запрос.
2. Подключить микрофон и дождаться запуска агента; проверить слышимый ответ.
3. Сказать «Алматыдағы кеңселеріңіз қайда?» и «Сақтандыру бойынша терапевтке жазып қойыңызшы».
4. Проверить mixed: «Маған терапевтке жазылу керек, и ещё список клиник в Алматы», затем сменить тему.
5. Проверить очередь, preview расторжения и подтверждение обычной следующей репликой, handoff и его контекст.
6. Проверить отказ микрофона, autoplay, переподключение, восстановление потерянной трассы и освобождение микрофона после завершения.
7. Создать новый диалог; проверить пустую историю и отсутствие поздних ответов предыдущей сессии.

Сохранить реальные request_id/turn_id и наблюдаемый результат. Живой голос пока не принят: при последней проверке локальный backend на 8000 был недоступен. Временные аппаратные mute/unmute микрофона отдельно не отслеживаются; отключение трека (ended) обрабатывается.
